## 1. Punto de partida: se estaba trabajando sobre el código equivocado

**Síntoma:** en el panel admin, *Propiedades* no cargaba absolutamente nada.

**Causa raíz:** la rama local `develop` se había creado con `git checkout -b develop`, que crea una rama **nueva y vacía** en el commit actual (`main`), en vez de traer la del remoto. El flag `-b` significa "creá una rama acá", no "traeme la del remoto".

```
* develop 0ed9584              ← sin upstream, contenido de main
  main    0ed9584 [origin/main]
  origin/develop → fd8bb74     ← 43 commits adelante
```

En el código de `main`, esa ruta es literalmente un placeholder:

```tsx
{ path: 'properties', element: <div className="p-4">Propiedades Admin</div> },
```

**Resolución:** se re-clonó el repositorio con `git clone -b develop <url>`. La rama quedó correcta y con upstream (`[origin/develop]`).

> Diferencia que causó el lío: `git clone -b develop <url>` y `git checkout develop` traen la rama del remoto ✅ · `git checkout -b develop` crea una rama nueva vacía ❌

**Nota:** durante el diagnóstico se perdieron ediciones sin commitear en 6 archivos de `Portal.Infrastructure/Persistence/` (Configurations + `PortalDbContextFactory.cs`). Eran una reimplementación manual de las migraciones EF que `develop` **ya tenía terminadas y commiteadas** (`20260805165305_InitialSchema`, `20260806150213_UbicacionAproximadaOpcional`), así que no hubo pérdida funcional.

## 4. PENDIENTES

### Pendiente 1 — Bug de Zod: no se puede crear un inmueble con una sola operación

**Archivo:** `FrontEndUrbanos/src/features/admin/properties/pages/InmuebleFormPage.tsx:37-39`

**Síntoma:** si se deja "En arriendo" desmarcado (o "En venta"), el submit falla con:

```
Invalid input: expected nonoptional, received undefined
```

El error aparece en `precioArriendo` y `adminArriendo`, campos que **ni siquiera están en pantalla**.

**Causa raíz:** el proyecto usa **zod 4.4.3**. El helper es:

```ts
const numeroOpcional = z
  .union([z.string(), z.number(), z.null(), z.undefined()])
  .transform((v) => (v === '' || v === null || v === undefined ? null : Number(v)))
```

En Zod 3, incluir `z.undefined()` en un union marcaba la clave del objeto como opcional. **En Zod 4 ya no**: la optionalidad se determina por `.optional()`, así que la clave sigue siendo requerida y `undefined` la rechaza. Cuando el checkbox está desmarcado el input nunca se monta, nunca se registra en React Hook Form, y llega `undefined`.

El comentario de las líneas 30–36 describe exactamente este escenario y dice que por eso aceptan `undefined` — la intención era correcta, pero el mecanismo dejó de funcionar al migrar a Zod 4.

**Arreglo propuesto:** agregar `.optional()` a `numeroOpcional`. Revisar `textoOpcional` (líneas 45–47), que tiene la misma forma y probablemente el mismo problema.

**Impacto actual:** obliga a marcar venta *y* arriendo. Por eso el inmueble id=1 quedó con ambas operaciones.

## 6. Cómo funciona la subida de imágenes (para referencia)

Útil porque el fallo es confuso de diagnosticar. Son 3 pasos y **el binario nunca pasa por el backend**:

| Paso | Quién | Qué hace |
| --- | --- | --- |
| 1 | Frontend → API | `POST /api/admin/inmuebles/{id}/imagenes/presign` — devuelve URL prefirmada |
| 2 | **Navegador → MinIO** | `PUT` directo a `http://localhost:9000/...` |
| 3 | Frontend → API | `POST /api/admin/inmuebles/{id}/imagenes` — registra metadatos |

El paso 1 **siempre funciona aunque MinIO no exista**, porque firmar una URL es criptografía local sin red. El fallo aparece recién en el paso 2 (`connection refused`). Por eso parece que "el backend está bien pero la imagen falla".

Restricciones del componente (`GaleriaImagenes.tsx`): JPG/PNG/WEBP, máximo 10 por inmueble, 10 MB por archivo, la primera queda como portada.

**Regla RF-077:** no se puede publicar un inmueble sin al menos una imagen. Esto es comportamiento **intencional**, no un bug — el backend responde `400` con `"No se puede publicar (RF-077). Falta: al menos una imagen."`
